问题与方向00

先看运行状态，再改配置

现在的控制台是十个平级的配置表单页，真正需要处理的事（待批准的配对、跑失败的定时任务、挂掉的后台作业）要逐页去翻。改版把「正在发生什么」放到前面，把配置收到侧栏下半部，并修掉一批显示逻辑问题。后端接口一个不加、一个不改。

现在的问题

01
十个 Tab 平铺，运行和配置混在一起 全局

会话、定时任务、作业这类每天看的页面，和网关端口、原始 YAML 这种一年改一次的页面挤在一排。

02
「保存并热重载」常驻顶栏 全局

在会话、作业页上也显示；改了什么、有没有没保存的改动，都看不出来。

03
73 个会话铺成 73 张大卡片 会话

每张都直接展示 Chat ID、Session UUID 和完整工作区路径；同一个聊天的多个会话被打散到列表各处。

04
弹窗套弹窗 会话 / 定时 / 作业 / 技能

对话记录、工作区文件、运行记录、作业日志、技能编辑全是模态框，看完一个才能看下一个，没法对照。

05
对话记录不渲染 Markdown 会话

助手回复按纯文本显示，[In reply to …] 前缀原样露出；运行记录那边却又会渲染，两处不一致。

06
原始值直出 定时任务 / 引擎

0 20 * * * America/New_York、绝对时间戳、以毫秒为单位的输入框（600000）。每行定时任务挂 6 个按钮。

07
每页顶部 4 张指标卡 会话 / 定时 / 作业

和下方筛选器重复（「启用 7」和筛选「启用」），占掉首屏三分之一。

08
状态不刷新 安全 / 会话

配对请求只在页面加载时取一次，会话列表不轮询；新的配对请求要手动刷新才看得到，可能已经过期。

09
部分配置只能改 YAML 网关

调度器（scheduler）和后台作业（jobs）的并发、超时、时区等设置在表单里没有入口。

改版方向

运行优先

侧栏分「运行」「配置」两组。概览只放需要处理的事和正在发生的事；导航上的角标只提示异常（失败、待批准、运行中），不显示总数。

一个聊天一个入口

会话按聊天分组。聊天 → 会话 → 对话记录 → 工作区文件在同一屏完成，跨页关联同一聊天的定时任务和后台作业。

说人话

cron 显示为「工作日 08:30」，时间显示为「9 小时后」，时长用「6分12秒」。ID 和路径收进复制按钮，需要时再看。

编辑有状态

配置修改先暂存。底部浮条显示「3 处未保存」，可以先看差异再保存；⌘S 保存并热重载，离开页面前提醒。

状态一套颜色

成功、静默、运行中、警告、失败五种状态全站统一配色和形状，深浅色主题各调一套。

自动刷新，按需轮询

运行类页面在可见时轮询并显示「x 秒前更新」，去掉散落在各页的刷新按钮；标签页隐藏时暂停。
